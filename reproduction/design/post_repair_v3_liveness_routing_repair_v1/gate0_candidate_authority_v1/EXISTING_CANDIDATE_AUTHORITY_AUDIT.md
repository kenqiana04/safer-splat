# Existing candidate authority audit (source at upstream 919c5518)

- `runtime_types.py:33-37` has only `CandidateRole.PRIMARY` and `ALTERNATIVE`; there is no dedicated `CandidateSource` enum. `make_candidate` (`:283-288`) marks only strings `PRIMARY_NATIVE_CBF_QP` and `SOURCE_NATIVE_EXISTING` lawful. A recovery source passed unchanged would be unlawful at C0.
- `c0_admission.py:13-23` requires finite 3-vector, exact snapshot state/map provenance, `lawful`, and componentwise actuator bounds; it does not clip. New source requires explicit prospective admission, not a forged `lawful=True` bit.
- `alternative_provider.py:10-22` accepts only `SOURCE_NATIVE_EXISTING`; absent supplier returns empty. The public `active_cycle.py:572-610` does wire this provider and, for a supplied native candidate, routes fresh binding/C0/L2/L3. The frozen real stack factory supplies no candidates. Existing alternative inventory is zero, not an implicit recovery generator.
- `runtime_types.py:236-263` creates `RuntimeStateSnapshot.identity` from trial ID, cycle index, numeric state, goal, map and dt. Candidate identity (`:283-288`) hashes vector, role and provenance (source/controller/timestamp/state/map/lawful). `make_action` (`:300-303`) hashes vector, action role, source identity and authority references. Consequently candidate IDs and selected-action IDs are **not** vector-equivalence keys. A distinct, precisely typed canonical control-vector key is needed for dedup, while emitted candidate/action identities must still use existing runtime constructors.
- Candidate order currently comes from provider enumeration; there is no recovery ordering authority. `supervisor.py:418-447` chooses fully certified navigation, valid retained backup, certified terminal, boundary. `route_transition` owns routing, `arbitrate` owns final selection, and PlantCommitAdapter owns execution. Existing PR107 transition rows distinguish primary/alternative candidate requirements and backup/terminal fallback; the table has no bounded-recovery source rows.
- `l3_runtime.py:18-34`, canonical `repaired_components.py:189-246` and `stack_factory.py:148-166` preserve L3 status/reason; however the formal trace did not expose per-attempt L3 FAIL reason/scope. The unified backup certifier has reason prefixes including `INITIAL_CANDIDATE_ACTUATOR_REJECT`, `IMMEDIATE_SEGMENT_NOT_CERTIFIED`, `ZERO_ACTUATOR_AUTHORITY`, `BACKUP_ACTUATOR_REJECT`, `BACKUP_SEGMENT_NOT_CERTIFIED`, `BACKUP_CERTIFICATION_BUDGET_EXHAUSTED`, `TERMINAL_CERTIFICATE_FAILED`. Current `Supervisor.classify_reason_scope` does not map these L3 FAIL prefixes; future typed carrier must be added before source activation.

**SHOULD_NEW_RECOVERY_USE_EXISTING_ALTERNATIVE_SOURCE? NO.** `SOURCE_NATIVE_EXISTING` promises a pre-existing native controller candidate, whereas this Gate 0 specifies new deterministic local commands. Reuse would conceal generation provenance and silently violate the frozen default alternative-source contract. Add `SOURCE_BOUNDED_LOCAL_RECOVERY_V1` in a versioned prospective source authority; keep existing native provider unchanged.
