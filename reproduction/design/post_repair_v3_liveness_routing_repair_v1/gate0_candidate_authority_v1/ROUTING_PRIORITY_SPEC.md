# Supervisor-only routing and priority

The existing `Supervisor.arbitrate` already prefers fully certified navigation > valid retained backup > certified terminal > assurance boundary (`supervisor.py:418-447`). Recovery is a prospective versioned extension that enters **only** after a failed primary; it uses existing `ALTERNATIVE_NAVIGATION` final action role but a new provenance source. The priority is: `PRIMARY_CERTIFIED > VALID_RETAINED_BACKUP > BOUNDED_RECOVERY_SEARCH > PREFETCHED_CERTIFIED_TERMINAL > ASSURANCE_BOUNDARY`. A valid backup is neither discarded nor invalidated to scan. Stale/invalid backup cannot execute or veto recovery if all other gates pass. Recovery PASS requires Supervisor's final exact identity/bundle/deadline check; terminal remains fallback. No method action at boundary.

Entry is exact conjunction: same-cycle L1 PASS, primary proposal present, primary C0 PASS, primary L2 PASS, primary L3 `FAIL` with typed `CANDIDATE_LOCAL_COMPUTATION` scope, no valid retained backup, current-state certified terminal **prefetch PASS and cached for this exact snapshot**, deadline OPEN, exact map/geometry/actuator/canonical transition/state/goal identity, recovery source registered, and key not exhausted. Only `BACKUP_SEGMENT_NOT_CERTIFIED` and `TERMINAL_CERTIFICATE_FAILED` (the latter only if it refers to the candidate's future terminal, not the current-state fallback) are admitted local L3 FAIL prefixes in V1; their nested reasons must also be typed candidate-local rather than global/unknown. `BACKUP_CERTIFICATION_BUDGET_EXHAUSTED` is not a safety FAIL trigger (deadline/unknown); `IMMEDIATE_SEGMENT_NOT_CERTIFIED` contradicts same-candidate L2/immediate facts or is immediate non-repairable; `ZERO_ACTUATOR_AUTHORITY`, actuator rejection, any unmapped reason and all L3 UNKNOWN are excluded. Exact classification must be additively carried and tested before runtime activation. This is option A's **explicit allowlist**, not treating all FAIL as recoverable. An unclassified FAIL follows frozen fallback, not recovery.

No recovery on missing primary proposal/QP error, primary C0 FAIL, primary L2 FAIL, or any primary L3 UNKNOWN. Those remain frozen routes; Gate 0 does not broaden trigger. Current-state terminal PASS is a prerequisite to scan, as in upstream design. If terminal prefetch FAIL/UNKNOWN, boundary or existing valid backup route, no search. Each local candidate rejection may advance to the next unseen candidate while OPEN; global/identity/unknown stops search and returns to Supervisor for cached terminal/boundary. When exhausted, Supervisor uses cached certified terminal if still exact and timely, else boundary. Deadline WARNING/EXPIRED forbids new search; existing Supervisor deadline/fallback semantics remain. Never fallback to u_des or zero unless independently certified terminal.

Rationale for allowlist: `stack_factory.py:148-166` passes unified backup-certifier reason unchanged, while `supervisor.py:38-58,320-324` lacks these FAIL prefix mappings. Only future local witness segment/terminal failure can plausibly change with the candidate's acceleration; structural/authority/timeout reasons cannot. Future implementation must add exactly these classification hooks and versioned, disjoint PR107 transition rows. No Coordinator-side policy tree or action selection. If exact-one routing cannot be achieved without reopening frozen method logic, block implementation.

Sampled-data causal contract: `p_(k+1)=p_k+dt v_k`, `v_(k+1)=v_k+dt u_k`, `∂p_(k+1)/∂u_k=0`, `∂p_(k+2)/∂u_k=dt²I`. L1/immediate positional safety is candidate-independent; recovery cannot repair immediate `h(p_(k+1))`. Candidate benefit is first reachable at k+2 and must be assessed by L2 and canonical L3, never from immediate p alone.
