# Trial-local monotone exhaustion key

Use `sha256(canonical_json(V1 ordered material))`, never the cycle-indexed `RuntimeStateSnapshot.identity` alone. Material fields: `canonical_numeric_state_bits_hash` (six frozen float32 state components, zero normalized, no decimal-print comparison), `goal_bits_hash`, `dt_bits`, `map_identity`, `SOURCE_BOUNDED_LOCAL_RECOVERY_V1`, `AXIS_EXTREMA_F32_V1`, `actuator_authority_identity`, `hard_geometry_authority_identity`, `canonical_transition_identity`, `certificate_backend_identity`, `backup_routing_class`. `backup_routing_class` is `NONE`, `INVALID`, or `EXHAUSTED`; `VALID` prohibits entry. This is a routing-context discriminator, not a token-ID dependency. A changed token with the same non-valid class does not alter certification inputs or justify rescan. A class transition can change the key; all other material identity changes do too. Deadline epoch and cycle epoch are excluded: they would let a fixed point rescan each cycle. Deadline OPEN is a separate per-stage gate; warning/expiry pauses the scan without changing the key. Keep exact map/artifact authority, not map name.

Creation only after exact trigger and terminal prefetch PASS, before first candidate evaluation. Trial-owned append-only record states `UNSEEN -> ACTIVE(cursor, attempted vector IDs, typed results) -> PAUSED(cursor) -> EXHAUSTED` or `SELECTED`; a structural/global UNKNOWN instead becomes `BLOCKED`. The cursor is the first unseen rank after dedup. No second internal scan of an identical key in one cycle. On later cycle with the same key, `PAUSED` may resume only unseen ranks under fresh L1/primary/identity/deadline/terminal gates; previous candidate certificate results are **never reused** for commit. `EXHAUSTED`, `SELECTED`, and `BLOCKED` never rescan under the identical key. A new key starts a new finite scan, never revives stale certificates. Incompatible map/geometry/actuator/transition/backend/source/generator/goal/dt/numeric-state/backup class invalidates the old record for routing but retains audit history. Persist across cycles only within one trial; clear on finalized trial, never across trial sessions.

Serialization: append-only record includes version, full key material hash plus typed identity refs, trial-local scan ID, lifecycle, next rank, ordered attempted vector hashes, rejection/selection refs, last cycle, last deadline observation and terminal-prefetch ref. Reject malformed or colliding material as `RECOVERY_EXHAUSTION_IDENTITY_UNKNOWN` (no scan). Trace exposes key, scan ID, lifecycle transition and cursor. The record is search suppression only, not action or certificate authority.
